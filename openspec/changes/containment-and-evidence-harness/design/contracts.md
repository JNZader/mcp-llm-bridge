## A. Auth, cookie, canonical Origin, CSRF, CORS, logout

Proposed `AuthRuntime` is created once. Request credential selection precedes validation:

```ts
type AdminCredentialMode =
 | {kind:"cookie"; encodedSession:string}
 | {kind:"bearer"; token:string}
 | {kind:"none"};
```

If the request has any `llm_gateway_admin` cookie, mode is `cookie` even when Authorization exists. Cookie mode validates canonical Origin, session, CSRF, then authorization. Only cookie-absent requests can use legacy Bearer JWT/static token without Origin/CSRF. ADMIN_TOKEN is authoritative when explicitly present; invalid ADMIN_TOKEN never falls back. No configured credential yields 503 `ADMIN_AUTH_NOT_CONFIGURED`.

Canonical Origin algorithm:
1. require exactly one HTTP `Origin` field-value for unsafe cookie mode; reject missing, duplicate fields, comma/space serialized multiple origins, bytes outside visible ASCII, `null`, and opaque origins;
2. WHATWG-parse one absolute URL; require http/https, empty credentials, path exactly `/`, empty query/fragment;
3. ASCII-lowercase scheme and DNS host; strip one terminal DNS dot before IDNA ASCII serialization; preserve IPv4 canonical decimal and bracketed compressed IPv6 serialization; remove port 80 for http and 443 for https, preserve other numeric ports;
4. compare the resulting `scheme://host[:port]` byte-for-byte to the startup-canonical `publicOrigin`.
`Referer` is always ignored and never a fallback.

Golden Origin cases:
- `HTTPS://EXAMPLE.COM:443` => `https://example.com`;
- `https://example.com./` => `https://example.com`;
- `http://127.0.0.1:80/` => `http://127.0.0.1`;
- `http://[0:0:0:0:0:0:0:1]:3000/` => `http://[::1]:3000`;
- reject credentials, non-root path, query, fragment, `file:`, `null`, missing, duplicate, `https://a, https://b`, embedded control/non-ASCII bytes, and sibling `https://admin.example.com` for `https://example.com`.

Session cookie:
`llm_gateway_admin=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJqdGkiOiIwMDAwMDAwMC0wMDAwLTQwMDAtODAwMC0wMDAwMDAwMDAwMDAiLCJhdWQiOiJtY3AtbGxtLWJyaWRnZS1hZG1pbiIsInN1YiI6Im9jdG9jYXQiLCJpYXQiOjE3NjcyMjU2MDAsImV4cCI6MTc2NzI1NDQwMH0.Zml4dHVyZS1zaWduYXR1cmU; HttpOnly; Path=/; Max-Age=28800; SameSite=Lax`; Domain omitted; Secure present exactly for HTTPS (remote mode requires HTTPS). JWT contains random 256-bit `jti`, audience `mcp-llm-bridge-admin`, issued/expiry times, and subject. No JWT is returned in query, fragment, JS-readable cookie, localStorage, or sessionStorage.

`GET /v1/admin/csrf` after a valid cookie generates `randomBytes(32)`, stores only SHA-256(token) keyed by jti in the process-local store, expiry `min(now+1800s,session.exp)`, rotates atomically, returns 200 `{"schema":"mcp-llm-bridge/csrf/v1","csrfToken":"AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA","expiresAt":"2026-01-01T00:30:00.000Z"}` and `Cache-Control:no-store`. Unsafe cookie methods require `X-CSRF-Token`, exact 32-byte base64url decode and timing-safe digest match. Session renewal/expiry, privilege change, rotation and logout invalidate the prior digest.

Middleware order: credential selection; cookie Origin; session; CSRF; CORS; admin authorization; rate; body; handler. CORS unit adds PATCH and `X-CSRF-Token`: allow methods exactly GET,POST,PUT,PATCH,DELETE,OPTIONS; headers Content-Type,Authorization,X-Project,x-api-key,X-CSRF-Token; credentials true only for an exact configured origin, never `*`. Valid preflight returns the framework-standard 204 with matching Allow-Origin, Allow-Credentials:true, Allow-Methods and Allow-Headers; invalid/missing preflight Origin returns 403 `{"error":"The request origin is not allowed.","code":"CSRF_ORIGIN_INVALID"}`.

`POST /v1/admin/logout`: canonical Origin always required. Valid session also requires CSRF. It deletes CSRF/revocation state and returns 204 empty with:
`llm_gateway_admin=; HttpOnly; Path=/; Max-Age=0; Expires=Thu, 01 Jan 1970 00:00:00 GMT; SameSite=Lax`, matching Secure and omitted Domain. A stale/invalid cookie is unauthenticated and same-origin logout still returns the identical 204 clear; wrong/missing Origin returns 403 without mutation. React and embedded clients call the route and clear only in-memory CSRF/legacy compatibility state. 401 clears memory and re-probes. Only 403 `CSRF_TOKEN_INVALID` causes one CSRF refresh and one retry.

WP-00 explicitly supports one process: CSRF, revocation, and provider registry are process-local. Multi-process deployment is rejected at startup when cookie admin mode is enabled (`ADMIN_MULTI_PROCESS_UNSUPPORTED`); shared session state is deferred, not an open decision.

```ts
const ATTEMPT_STATE=["queued","running","timed_out","available","unavailable","failed","cancel_confirmed"] as const;
type AttemptState=typeof ATTEMPT_STATE[number];
type RawFence =
 | {state:"idle"}
 | {state:"running"|"timed_out";generation:number;startedAtMs:number;deadlineMs:number;cancel:"unsupported"|"requested"}
 | {state:"settled";generation:number;settledAtMs:number;outcome:"available"|"unavailable"|"failed"}
 | {state:"cancel_confirmed";generation:number;settledAtMs:number};
```

For immutable provider set `P`, global raw permits = |P|, per-kind permits = providers of that kind, and each ID has capacity-one fence. Invariant: `outstandingRaw <= |P|`, per kind `<= kindCount`, per ID `<=1`. All unfenced IDs start in byte-sorted order in one scheduler turn. Consumer deadline 2000ms; generation hard-close 2250ms. Hard-close emits immutable timed_out rows but does not release raw permits. Cancellation is requested only through an explicit adapter method and releases only after `"confirmed"`; AbortSignal alone is not confirmation. Late settlement never mutates an emitted snapshot and may seed only the next generation if still within evidence TTL. TTL is 10000ms from completedAt; refresh is single-flight; ID fixture is `health:1:aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa`; production format is literal prefix `health:`, base-10 generation, colon, and 64 lowercase SHA-256 hex characters. With four first providers hung, all later providers still start. With every provider hung, later generations complete with queued `PREVIOUS_RAW_OPERATION_OUTSTANDING` rows. Duplicate/post-freeze registration tests are mandatory.

## E. Scanner contract

`paths.bin`: bytes `WP00PTH\0`; BE u16 version=1,u16 flags=0,u32 count; each sorted record BE u32 UTF-8 path length, path bytes, u32 normalized Git mode, u64 byte length, 32 raw SHA-256 bytes. Reject invalid UTF-8/NUL/absolute/dot/traversal/backslash/duplicate; no Unicode normalization. Modes: tracked 100644/100755/120000 only; untracked regular 100644/100755, symlink 120000; special files fail. Hash symlink target bytes; absolute/escaping link fails; in-root target must be inventoried.

Canonical manifest is RFC 8785 JSON Canonicalization Scheme UTF-8: object keys sorted by UTF-16 code units, arrays retained, integers base-10 without leading zero, no floats, JSON escapes only mandated characters using lowercase hex, duplicate keys rejected before canonicalization, strings preserved without Unicode normalization, final newline absent. Hash domain:
`wp00ArtifactHash=SHA256(UTF8("wp00-artifact-v1\0")||paths.bin||JCS(manifest without hash fields))`.
Provider `subject_hash` remains opaque and separate. `bindingHash=SHA256(UTF8("wp00-provider-binding-v1\0")||UTF8(providerSubjectHash)||rawWp00Hash)`.

Parser registry:
- `ts-estree-v1`: TypeScript 5.9.3, integrity `sha512-jl1vZzPDinLr9eUt3J/t7V6FgNEw9QjvBPdysz9KfQDD41fQrC2Y4vKQdiaUpFT4bXlb1RHhLpp8wtm6M5TgSw==`; TS/TSX/JS/JSX/MTS/CTS/MJS/CJS, static import/reexport/alias/wrapper/callback/factory/spread boundaries;
- `package-json-v1`: strict RFC 8259 parser, duplicate-key rejection; scripts/bin/main/module/exports/files/workspaces;
- `posix-shell-v1`: lexical simple commands, quotes, escapes, assignments, pipes, &&, ||, ;, subshell and command substitution; dynamic eval/indirect expansion unresolved=>fail;
- `github-actions-yaml-v1`: indentation subset for jobs/steps/uses/run/shell/working-directory/env; aliases/tags/merge keys/custom types fail;
- `dockerfile-v1`: escape directives, FROM/RUN/CMD/ENTRYPOINT/COPY/ADD/WORKDIR/USER/ENV in shell/JSON forms; ONBUILD/heredoc/dynamic stage/path unresolved=>fail;
- `compose-yaml-v1`: services image/build/command/entrypoint/volumes/network_mode/user/working_dir/environment; unsupported alias/tag/extension affecting execution fails.

Root parsing is split by grammar behind one closed, deterministic contract; it is not a claim to implement full POSIX shell or general YAML. The planned modules are `test/contracts/scanner/root-api.mjs`, `root-inventory.mjs`, `package-json.mjs`, `posix-shell.mjs`, `github-actions-yaml.mjs`, `dockerfile.mjs`, `compose-yaml.mjs`, and `root-integration.mjs`. `test/contracts/outward-scanner.mjs` remains the CLI plus the admitted SCAN-BIN codec/hash owner and imports these modules directly; the scanner directory is not a barrel.

The caller passes `expected` separately from parser-controlled input; it is constructed only after SCAN-BIN validates the authoritative paths.bin/artifact/provider binding and is never derived from `input`. Before parsing, path, mode, length, and SHA-256 of `input.bytes` must exactly match `expected.record`, the record path must occur exactly once in `expected.inventoryPaths`, and binding/artifact identities must already be admitted; any mismatch rejects. Outputs sort edges by JCS byte order and diagnostics by `(path,line,column,field,code)`; diagnostics expose stable codes and locations, never source fragments, commands, environment values, or credentials. Unsupported execution-affecting syntax, ambiguous or duplicate structures, and unresolved or dynamically constructed execution semantics can only produce `rejected`; supported commands in every listed grammar produce `parsed`, and partial success is forbidden. Each bounded internal parser implements only the registry subset above and rejects everything outside it. Adding a parser dependency requires a separate primary-documentation and integrity review; no new dependency is selected by this design. Every listed registry construct remains required: an implementation packet that cannot support its entire normative subset within its ceiling must stop at a parser-selection research gate, not silently narrow the grammar or relabel required syntax as unsupported.

`SCAN-ROOT` becomes an aggregate integration gate over seven bounded prerequisites: `SCAN-ROOT-API`, `SCAN-ROOT-INVENTORY`, `SCAN-ROOT-PACKAGE`, `SCAN-ROOT-SHELL`, `SCAN-ROOT-ACTIONS`, `SCAN-ROOT-DOCKER`, and `SCAN-ROOT-COMPOSE`. Integration owns generated/root/devcontainer classification, registry dispatch, manifest assembly, and zero-unparsed-root proof. The 16 existing scenarios remain unchanged and are allocated in pairs in that order: API 01-02, inventory 03-04, package 05-06, shell 07-08, Actions 09-10, Dockerfile 11-12, Compose 13-14, integration 15-16.
